En sandlåda för AI-agenter

A sandbox for AI agents

Kristian Eide · 11 juli 2026 · 3 min läsning
Kristian Eide · July 11, 2026 · 3 min read

Det snabbaste sättet att göra en kodagent användbar är att ge den självständighet: låta den köra kommandon, installera paket, köra tester och iterera. Det snabbaste sättet att ångra sig är att ge den självständigheten på din egen dator. Så: ge agenten en egen dator.

The fastest way to make a coding agent useful is to give it autonomy: let it run commands, install packages, execute tests, iterate. The fastest way to regret it is to give it that autonomy on your own machine. So: give the agent a machine of its own.

Jag har byggt en liten proof of concept som gör precis det — en Docker-sandlåda som kör en kodagent (GitHub Copilot CLI i det här fallet) i en isolerad Linux-microVM, med verktygen den behöver förinstallerade: .NET, Azure CLI, Playwright, Node, Python, Go. Tre idéer bär hela upplägget.

I've built a small proof of concept that does exactly that — a Docker sandbox that runs a coding agent (GitHub Copilot CLI, in this case) inside an isolated Linux microVM, with the tools it needs pre-installed: .NET, Azure CLI, Playwright, Node, Python, Go. Three ideas carry the whole thing.

Isolering som standard

Isolation by default

Agenten jobbar inte på min dator; den jobbar i en virtuell engångsmaskin som råkar ha mitt projekt monterat. Allt den gör stannar i lådan. När uppgiften är klar raderar ett kommando hela maskinen — och eventuell röra försvinner med den.

The agent doesn't work on my computer; it works in a disposable virtual machine that happens to have my project mounted into it. Everything it does stays inside the box. When the task is done, one command deletes the whole machine — and whatever mess was made goes with it.

Nätverket är deny-all

The network is deny-all

Inifrån sandlådan existerar internet i princip inte. Utgående trafik går genom en proxy med deny-all som grundregel och en kort tillåtelselista: GitHub, paketflödena vi använder, Azure DevOps. Allt annat blockeras. Till och med npm-registret är avstängt i körläge — paketen agenten behöver bakas in i imagen när den byggs, så den kan inte luras att hämta hem och köra godtycklig kod. Och om en prompt-injektion någon gång övertalar agenten att läcka något, finns det väldigt få ställen kvar att skicka det till.

From inside the sandbox, the internet mostly doesn't exist. Outbound traffic passes through a proxy with a deny-all policy and a short allowlist: GitHub, the package feeds we rely on, Azure DevOps. Everything else is blocked. Even the npm registry is shut off at runtime — the packages the agent needs are baked into the image when it's built, so it can't be tricked into pulling down and running arbitrary code. And if a prompt injection ever talks the agent into leaking something, there are very few places left to send it.

Nycklarna bor i proxyn

The keys live in the proxy

Agenten konfigureras aldrig med inloggningsuppgifter. En liten reverse proxy inne i sandlådan injicerar rätt Authorization-header för rätt värd — en GitHub-token för GitHubs API, en Azure DevOps-PAT för Azure DevOps. Reglerna är ren JSON, så att lägga till en tjänst är konfiguration snarare än kod, och kortlivade SSO-tokens fungerar lika bra som långlivade personliga access-tokens.

The agent is never configured with credentials. A small reverse proxy inside the sandbox injects the right Authorization header for the right host — a GitHub token for the GitHub API, an Azure DevOps PAT for Azure DevOps. The rules are plain JSON, so adding a service is configuration rather than code, and short-lived SSO tokens work just as well as long-lived personal access tokens.

Sätt skyddsräckena i miljön, inte i användarens vaksamhet.
Put the guardrails in the environment, not in the operator's vigilance.

Vad det möjliggör

What it allows

Full självständighet utan fullt förtroende. Agenten kan köras i det läge där den faktiskt är produktiv — ingen bekräftelsefråga före varje kommando — eftersom sprängradien är en engångs-VM med stängt nätverk, inte din laptop.

Full autonomy without full trust. The agent can run in the mode where it's actually productive — no confirmation prompt before every command — because the blast radius is a disposable VM with a closed network, not your laptop.

Arbete mot privat kod och interna system. Proxymönstret låter agenten prata med privata repon och Azure DevOps utan att någon klistrar in tokens i dess konfiguration.

Work against private code and internal systems. The proxy pattern lets the agent talk to private repositories and Azure DevOps without anyone pasting tokens into its configuration.

Miljöer som vem som helst kan starta. Ett skript bygger imagen, startar sandlådan, applicerar nätverkspolicyn och drar igång proxyn. Det är den delen jag bryr mig mest om: när skyddsräckena bor i miljön i stället för i användarens vaksamhet, slutar det vara vårdslöst att låta fler i en organisation köra agenter.

Environments anyone can start. One script builds the image, starts the sandbox, applies the network policy and launches the proxy. That's the part I care most about: when the guardrails live in the environment instead of in the operator's vigilance, letting more people in an organisation run agents stops being reckless.

Vart det här är på väg

Where this is heading

Det här är en proof of concept, byggd runt Copilot CLI — men inget i mönstret är specifikt för just den agenten. Samma recept fungerar för vilken agent som helst som går att köra i en terminal: isolera, tillåtelselista, injicera. Koden finns på GitHub, och i kommande inlägg tänker jag gräva i de enskilda delarna.

This is a proof of concept, built around Copilot CLI — but nothing in the pattern is specific to that agent. The same recipe works for any agent you can run in a terminal: isolate, allowlist, inject. The code is on GitHub, and in future posts I'll dig into the individual pieces.
